## 문제

3. (5점) Lock-free queue(무잠금 큐)의 enqueue(삽입)에서 어떤 스레드가 `tail->next` CAS(비교 후 교환)는 성공했지만 `tail` 갱신 전에 멈췄다고 하자. 다른 스레드가 `tail`을 대신 전진시켜야 하는 이유를 쓰시오.

4. (5점) Lock-free stack(무잠금 스택)에서 Elimination(소거) 기법이 일반 lock-free stack(무잠금 스택)보다 고경쟁 상황에서 성능이 좋아질 수 있는 이유를 쓰시오.

5. (10점) Consensus object(합의 객체)의 조건을 3가지 이상 쓰고, atomic read/write(원자적 읽기/쓰기)의 consensus number(합의수)와 CAS(비교 후 교환)의 consensus number(합의수)가 각각 무엇인지 설명하시오.

## 정답 및 채점 기준

1. CAS(compare-and-swap/compare-and-set, 비교 후 교환)는 메모리 값이 expected(기대값)와 같을 때만 update(새 값)로 바꾸고 true를, 아니면 false를 반환한다. load/store(읽기/쓰기)만으로는 "읽은 값이 아직 그대로일 때만 구조를 바꾸는" 조건부 갱신이 안 되어, queue/list/stack(큐/리스트/스택)의 링크 변경 충돌을 안전하게 해결하기 어렵다.

2. lock-free(무잠금) 탐색 중인 다른 스레드가 삭제된 노드 주소를 아직 들고 있을 수 있으므로 즉시 delete(삭제)하면 use-after-free(해제 후 사용), page fault(페이지 폴트), ABA 문제가 생길 수 있다. 모든 활성 스레드의 local epoch(지역 에폭)가 그 노드가 retire(퇴역)된 epoch(에폭)보다 뒤로 지나갔을 때 재사용 가능하다.

3. tail(꼬리 포인터)이 낡은 노드를 계속 가리키면 다른 enqueue(삽입)들이 새 노드 뒤에 붙지 못하고 같은 실패를 반복할 수 있다. 모든 스레드가 tail 전진을 도와야 한 스레드의 중단이 전체 진행을 막지 않아 non-blocking(비멈춤) 성질을 유지한다.

4. push(삽입)와 pop(삭제)이 동시에 만나면 스택 top(최상단 포인터)에 CAS(비교 후 교환)를 하지 않고 값을 직접 교환해 두 연산을 Elimination(소거)할 수 있다. 고경쟁 상황에서 top 하나에 몰리는 CAS 충돌을 줄여 병렬로 완료되는 연산 수가 늘어난다.

5. 모든 decide(결정) 호출은 같은 값을 반환한다. 반환값은 제안된 값 중 하나다. 각 스레드는 한 번 이하로 호출하고 wait-free(무대기)/atomic(원자적)하게 동작해야 한다. atomic read/write(원자적 읽기/쓰기)의 consensus number(합의수)는 1, CAS(비교 후 교환)의 consensus number(합의수)는 무한대다.

6. ABA는 포인터 값이 A에서 B로 바뀌었다가 다시 A가 되어 CAS(비교 후 교환)가 변경 사실을 못 보는 문제다. stamped pointer(스탬프 포인터)는 포인터에 version/stamp(버전/스탬프)를 붙여 변경 때마다 stamp를 바꾼다. 다만 64/128bit atomic load/store(원자적 읽기/쓰기), 정렬, 성능 문제가 생긴다. `atomic<shared_ptr<T>>`(원자적 shared_ptr)는 참조 카운트로 재사용을 막지만 내부 lock(잠금) 때문에 느리거나 lock-free(무잠금)가 아닐 수 있다. EBR(에폭 기반 메모리 회수)/Hazard Pointer(해저드 포인터)는 안전한 메모리 재사용 시점을 관리하지만 구현 비용과 스레드 상태 관리 비용이 있다.

7. SkipList(스킵리스트)는 한 노드가 여러 레벨 링크에 동시에 나타나므로 Add(추가) 중 0레벨만 연결되고 윗레벨이 아직 없거나, Remove(삭제) 중 어떤 레벨만 끊긴 상태가 생긴다. `fullyLinked`(완전 연결 여부)가 false인 노드는 아직 집합에 있다고 보면 안 된다. Remove는 먼저 `marked/removed`(마킹/삭제 표시)로 논리 삭제를 표시하고, 물리 삭제는 보통 위 레벨부터 링크를 끊어 검색 오류를 줄인다. lock-free skip list(무잠금 스킵리스트)는 0레벨 연결/마킹을 실제 존재 여부의 기준으로 삼는다.

8. A: X, B: X, C: O, D: O, E: O

9. A: O, B: O, C: X, D: X, E: O

10. A `old_top`, B `old_top`, C `new_node`, D `old_top->next`, E `old_top`, F `new_top`, G `old_top->data`

11. A `nullptr`, B `node`, C `last`, D `node`, E `last`, F `next`, G `++global_epoch` 또는 `g_epoch.fetch_add(1)+1`, H `INF` 또는 `numeric_limits<long long>::max()`, I `<`. `else`는 다른 스레드가 링크는 성공했지만 tail 이동을 끝내지 못한 상태를 도와 queue의 꼬리 포인터를 최신 상태로 만들기 위해서다.

## 추가 O/X 연습: 기말 범위 함정형

1. lock-free(무잠금) 자료구조는 mutex(상호배제 잠금)를 쓰지 않으므로 항상 blocking(멈춤 가능) 자료구조보다 빠르다. ( )
2. `thread_local`(스레드 지역) free list(해제 리스트)는 allocator contention(할당자 경쟁)을 줄일 수 있지만, 삭제 노드의 안전한 재사용 문제를 자동으로 해결하지는 않는다. ( )
3. OpenMP(오픈MP) `for`는 loop-carried dependency(반복 간 의존성)를 자동으로 분석해 안전하지 않으면 병렬화를 막아 준다. ( )
4. TBB(Threading Building Blocks, 스레딩 빌딩 블록) `parallel_for`(병렬 for)는 작업 범위를 나누어 실행하지만, 공유 변수 갱신의 data race(데이터 레이스) 책임은 프로그래머에게 남아 있다. ( )
5. `cache_aligned_allocator`(캐시 정렬 할당자)는 false sharing(거짓 공유) 완화와 관계가 있다. ( )
6. CUDA(쿠다) 기본 예제에서 host(호스트) 메모리와 device(디바이스) 메모리는 구분되고, 보통 `cudaMemcpy`(쿠다 메모리 복사)가 필요하다. ( )
7. Transactional Memory(트랜잭션 메모리)는 여러 word(워드) 변경을 하나의 atomic(원자적) 구간처럼 보이게 하려는 모델이다. ( )
8. HTM(Hardware Transactional Memory, 하드웨어 트랜잭션 메모리)은 충돌이 심하거나 transaction(트랜잭션)이 너무 크면 abort(중단)가 늘어 성능이 나빠질 수 있다. ( )
9. `concurrent_unordered_map`(병행 unordered_map)의 모든 메서드는 STL map처럼 아무 제약 없이 thread-safe(스레드 안전)하다. ( )
10. spin loop(스핀 반복문)에서 `_mm_pause()`는 busy waiting(바쁜 대기) 중 CPU 자원 낭비와 HyperThreading(하이퍼스레딩) 간섭을 줄이는 데 도움이 될 수 있다. ( )

# 고급 멀티쓰레드 프로그래밍 시험직전 암기요약

## 1. 진행 보장

```text
wait-free(무대기) ⊂ lock-free(무잠금) ⊂ non-blocking(논블로킹)
```

- wait-free: 모든 스레드가 유한 단계 안에 완료.
- lock-free: 전체 중 누군가는 계속 완료. 개별 스레드 starvation(기아)은 가능.
- non-blocking: lock 잡은 스레드 때문에 전체가 막히는 상황을 피함.
- 모든 wait-free는 lock-free이다. O
- 모든 lock-free는 wait-free이다. X

## 2. CAS와 합의수

- CAS(compare-and-swap, 비교 후 교환): 값이 expected와 같을 때만 update로 바꿈.
- atomic read/write register(원자적 읽기/쓰기 레지스터)의 consensus number(합의수)는 1.
- FIFO queue(선입선출 큐)의 consensus number는 2.
- CAS의 consensus number는 무한대.
- CAS는 `EMPTY -> 내 값`을 최초 1명만 성공시킬 수 있어서 무한대 합의가 가능하다.

## 3. ABA와 메모리 회수

- ABA: 포인터가 A -> B -> A로 돌아와 CAS가 중간 변경을 못 보는 문제.
- stamped pointer(스탬프 포인터): 포인터 + stamp/version을 같이 비교해서 ABA를 막음.
- stamp를 써도 delete된 노드 접근 문제는 자동으로 해결되지 않는다.
- 즉시 `delete`하면 다른 스레드가 들고 있던 옛 주소를 접근해 use-after-free(해제 후 사용), page fault(페이지 폴트)가 날 수 있다.
- free-list(해제 리스트): OS/C library에 바로 반환하지 않고 재사용하려고 보관.
- free-list만으로 즉시 재사용 안전이 보장되지는 않는다. EBR/Hazard Pointer가 필요.

## 4. EBR

- EBR(Epoch Based Reclamation, 에폭 기반 메모리 회수)은 삭제 노드를 바로 delete하지 않고 retire list에 보관.
- 모든 활성 스레드의 local epoch가 삭제 노드의 retire epoch보다 뒤로 지나가면 재사용 가능.
- 어떤 스레드가 method 안에서 오래 멈추면 local epoch가 오래 남아서 재사용이 지연될 수 있다.
- 핵심 답안:

```text
다른 스레드가 삭제 노드 주소를 아직 들고 있을 수 있으므로 즉시 delete하지 않는다.
모든 활성 스레드가 그 노드를 볼 수 없는 epoch로 지나간 뒤 재사용한다.
```

## 5. Lock-Free Queue

enqueue(삽입)는 2단계:

```text
1. tail->next에 새 노드 연결
2. tail을 새 노드로 전진
```

- `tail->next` CAS 성공 = 새 노드는 이미 queue에 들어감.
- 그 뒤 `tail` CAS가 실패해도 enqueue는 성공이다.
- 실패 이유는 다른 스레드가 tail을 이미 밀어줬을 수 있기 때문.
- `tail->next != nullptr`이면 tail이 진짜 꼬리가 아니라 뒤처진 상태.
- 다른 스레드가 `tail`을 `next`로 밀어주는 helping(도와주기)이 필요.
- helping이 없으면 `tail->next` 연결 후 멈춘 스레드 때문에 다른 스레드들이 기다려 blocking이 될 수 있다.

암기 코드:

```cpp
if (next == nullptr) {
    if (CAS(&last->next, nullptr, e)) {
        CAS(&tail, last, e);
        return;
    }
} else {
    CAS(&tail, last, next);
}
```

## 6. Lock-Free Stack, Backoff, Elimination

push:

```cpp
old_top = top;
new_node->next = old_top;
CAS(&top, old_top, new_node);
```

pop:

```cpp
old_top = top;
new_top = old_top->next;
CAS(&top, old_top, new_top);
```

- stack은 top 하나에 CAS가 몰려 contention(경쟁)이 커질 수 있다.
- backoff(백오프): CAS 실패 후 잠시 기다려 충돌 감소. 너무 오래 기다리면 손해.
- elimination(소거): push와 pop이 만나면 central stack에 접근하지 않고 값을 직접 교환.
- push-push는 소거 불가. pop-pop도 소거 불가.
- 경쟁이 낮으면 elimination 시도 비용이 오히려 손해일 수 있다.

## 7. SkipList

- SkipList는 한 노드가 여러 level(레벨)에 걸쳐 있어 add/remove 중간 상태가 복잡하다.
- 노드가 집합에 존재:

```text
fullyLinked == true && marked == false
```

- `fullyLinked == false`: add 중간 상태. 아직 집합에 있다고 보면 안 됨.
- `marked == true`: remove가 시작된 논리 삭제 상태.
- Add는 아래 level부터 위 level로 연결하고 마지막에 `fullyLinked = true`.
- Remove는 먼저 `marked = true`, 그 뒤 위 level부터 아래 level로 링크 제거.
- Find는 각 level의 `preds[]`, `succs[]`를 저장한다.
- lock 후 validation 실패하면 unlock 후 처음부터 다시 find.

## 8. Universal Construction

NODE 구조:

```cpp
class NODE {
public:
    Invocation invoc;
    Consensus decideNext;
    NODE* next;
    volatile int seq;
};
```

- `invoc`: 메서드 호출 정보. 예: `enqueue(10)`, `remove(3)`.
- `decideNext`: 여러 후보 next node 중 하나를 합의하기 위한 consensus object.
- `next`: 실제 다음 로그 노드.
- `seq`: 로그 순서 번호.
- 모든 연산을 log에 순서대로 붙이고, 같은 순서로 객체 상태를 재현한다.

## 9. TAS / TTAS

- TAS(Test-And-Set): spin 중에도 계속 atomic write/RMW를 시도.
- TAS는 cache line을 독점하려 해서 invalidate, cache miss, bus traffic이 많다.
- TTAS(Test-Test-And-Set): lock이 잡혀 있는 동안 read만 하며 spin.
- TTAS는 cache line 공유가 가능해 TAS보다 보통 빠르다.
- 단, unlock 순간에는 여러 스레드가 한꺼번에 TAS를 시도해 bus traffic이 생길 수 있다.

## 10. 라이브러리 함정

- TBB `concurrent_queue`: `empty() == false`여도 바로 다음 `try_pop()` 성공 보장 X.
- TBB `concurrent_hash_map`: `accessor`를 오래 들고 있으면 다른 스레드 성능에 영향 O.
- OpenMP `parallel for`: data race를 자동으로 해결하지 않음. reduction/atomic/critical 필요.
- CUDA: host memory와 device memory는 구분됨. 보통 `cudaMemcpy` 필요.
- Transactional Memory: 충돌 많거나 transaction이 크면 abort가 늘어 성능 저하.

## 11. 헷갈리는 OX만 외우기

- `tail->next` CAS 성공 후 `tail` CAS 실패면 enqueue 실패다. X
- stamped pointer면 delete 문제까지 자동 해결된다. X
- ABA는 queue에서만 생긴다. X
- CAS 실패는 다른 스레드의 성공일 수 있다. O
- `fullyLinked == false`인 노드는 집합에 존재한다고 판단하면 안 된다. O
- skip list remove는 marked 없이 바로 링크 제거해도 항상 안전하다. X
- push와 pop은 elimination 가능하다. O
- push와 push는 elimination 가능하다. X
- atomic read/write register의 합의수는 1이다. O
- CAS의 합의수는 무한대이다. O
